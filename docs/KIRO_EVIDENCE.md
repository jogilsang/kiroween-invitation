# Kiro usage evidence (dated)

This file records, with dates, how Kiro was used to build ASCII Invite. The
Kiro usage write-up (submission) is derived from this file. No claim is made
here that cannot be checked against the repo (`.kiro/`, commits, tests).

Honesty note: this project was driven through the Kiro CLI with a custom agent
(`kiroween`) acting as router/conductor. The `.kiro/specs`, `.kiro/steering`,
`.kiro/hooks`, and `.kiro/agents` files in this repo are the actual artifacts
that drove and constrained the build. Where an artifact was authored by the
agent rather than generated by a GUI wizard, that is stated plainly.

## 2026-11-05 — Project scaffold (step 2)

- Created repo root `ascii-invite/` with engine/app split, MIT LICENSE visible
  at root, `.gitignore` that excludes `.omc/` but intentionally keeps `.kiro/`
  (Kiroween requires `/.kiro` at root; ignoring it risks disqualification).
- `package.json`: `type: module`, `node --test` as the test runner, `fast-check`
  as the only dev dependency (for property-based testing).
- Node 26.3.1 / npm 11.16.0 confirmed (Kiroween docs reference Node 22.12+).

## Steering (step 3)

- See `.kiro/steering/`. Each steering doc opens with a one-line "why" and the
  effect it is meant to have on the build.

## Specs (step 4)

- See `.kiro/specs/ascii-invite/{requirements,design,tasks}.md`. Requirements
  use EARS form with explicit negative paths. Tasks are sized to be individually
  verifiable, each naming its test.

## Hooks (step 5)

- See `.kiro/hooks/`. When a hook actually catches something, it is logged here
  with the date and what it caught.

## Custom agents (step 6)

- Five custom agents under `.kiro/agents/`, with `kiroween` as router/conductor.
  Scope boundaries and what each produced are recorded as work proceeds.

## Property-based testing (step 7)

- See `tests/pbt.test.js`. Properties and any bug PBT caught that unit tests
  missed are recorded here with dates.
